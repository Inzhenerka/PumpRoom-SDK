# v2

## 2.4.1 – Проверка конфигурации и документация

- Добавлена проверка обязательных параметров `apiKey` и `realm`; ошибки настройки доверенных origins стали понятнее.
- Уточнены инструкции для on-premises: адрес API и доверенные origins нужно задавать вместе.

## 2.4.0 – SCORM

Сайт SDK можно размещать в подкаталоге общего сайта PumpRoom.

Добавлена поддержка SCORM 1.2 и 2004: получение данных ученика и сохранение результатов задания в LMS.

Добавлены методы для монтирования задания через iframe.

## 2.3.1 – Результаты прохождения заданий

Добавлен коллбэк `setOnTaskResultChangedCallback` для получения сохранённого результата задания и его изменений. Результат содержит статус прохождения, статус успешности, оценку, прогресс и ревизию. Сайт SDK теперь поставляется в Docker-образе и формирует ссылки на bundle из текущего origin, поэтому один образ подходит для cloud и on-premise.

## 2.2.0 – Поддержка on-premise

Добавлена настройка `trustedOrigins` для проверки источников сообщений от iframe, `apiBaseUrl` для on-premise установок и `pageUrl` для стабильной идентификации SCORM-контента. Исправлено кеширование авторизации при смене пользователя LMS.

## 2.1.0 – Обновление контракта данных задания

Обновлён контракт `TaskDetails`: поле `description` больше не передаётся в коллбэки загрузки и отправки задания. Для идентификации задания используйте поле `uid`.

## 2.0.0 – Обновление контракта авторизации LMS

Поля `lms` и `profile` в запросе авторизации заменены на единое поле `identity`. Поле `LMSIdentityInput.email` удалено, идентификатор студента передается в `identity.id`.

В `LMSIdentityInput` добавлено обязательное поле `provider`. Для обычной LMS-интеграции используйте `lms`.

В `LMSIdentityInput` добавлены необязательные поля `name` для отображаемого имени и `language` для передачи языка студента. Также добавлено поле `provider_extra` для дополнительных данных провайдера.
